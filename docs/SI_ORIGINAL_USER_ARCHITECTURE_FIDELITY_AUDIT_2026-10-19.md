The conducted v0–v26 experiments instead tested a small proxy whose module docstring itself says **"CPU-first mechanism study, not an SI model"**, followed by PCMA-v1 developments and benchmark ports. Source images came from the user in the project conversations, including screenshots restated on 2026-10-19. They describe a high-level *functional system*, NOT a uniquely implementable layer-by-layer parameterization. Details below are requirements from the supplied description; specific implementation choices require an explicit, versioned design freeze, and must be labeled as engineering interpretations.

### How to recover the original research goal without moving the goalposts

1. **Source-of-truth fidelity freeze:** Maintain one architecture design ledger mapping every screenshot requirement to one implemented module, interface, training objective, test and measurable ablation. Distinguish user-specified functional requirement from researcher's implementation choice. No performance claim until a faithful code audit and end-to-end interaction tests pass. There is no universally agreed exact parameterization in the screenshots; engineering decisions cannot be passed off as user-specified facts.
2. **First working faithful integration (no architecture-superiority claim yet):** Implement shared multimodal embeddings and action pathways; hybrid recurrent-attention + sparse experts; ACT-style iterative latent compute and measurable early exit; action-conditioned latent rollout and actual multi-step planning; working/fast/long-term memory *wired into inference and factual updates*; replay + continual-learning skill modules; calibrated verifier controlling re-evaluation. Test a small instance first for correctness, then scale as budget permits.
3. **Predeclared causal interaction tests:** Verify a truly active path for each module (not inert parameters or interface stubs), including actual net effect and compute cost. Tests must catch unexecuted memory, fixed-depth "adaptive" loops, hallucinated simulator state, data/target leakage, replay-induced forgetting, multimodal-tag-only shortcuts, verifier leakage and invalid rollout.
4. **One fair, frozen architectural competition:** Train the *same complete original candidate* vs a dense/modern Transformer **with matched input encoders, memory/search/feedback/replay budget**; then strong cheap classical/retrieval/belief systems. Match active train and inference FLOPs as well as training tokens/data, not only parameter counts or 48 optimizer steps. Include multiple independent training seeds, long-horizon changes, text/image/audio/action tasks, compute-efficiency, uncertainty and robust heldout families; claim only what each evaluation measures. Component-wise ablations are essential; superiority of added compute alone is not a mechanism.
5. **Scientific authorization and stop rule:** Reconcile consumed scientific seed/attempt ledger across this SI branch and the repo BEFORE reserving any new attempt, freeze independent unseen evaluations, effect-size and clustered uncertainty thresholds, code/weight/tree digests and budget. No reuse of consumed v25/v26 seeds, no paid Colab/Modal/GPU without explicit user-approved expense and no retrospective hyperparameter changes to rescue a negative.
6. **Stop honestly:** If the faithful integrated candidate is infeasible at the available budget, record **INSUFFICIENT RESOURCES / NOT TESTED**, not architecture failure. If it is feasible and loses under a preregistered fair comparison, record an actual **NO-GO** for *that concrete implementation* and distinguish it from any untested scale or future architecture.
