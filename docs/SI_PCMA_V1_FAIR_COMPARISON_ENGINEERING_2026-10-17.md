## Newly implemented scope
1. **Compact GRU comparator:** `PCMAGRURewardPredictor` receives the same 3 observation features, 4 action features, and modality tags as original hybrid and Transformer. It exposes the same factual-outcome training interface. This GRU is **unmatched in parameters and active compute**; it must be reported as a compact baseline, never as proof of matched equality. A frozen GRU policy may use exactly the same `PCMAState` memory/online-adapter APIs; its backbone does not update during deployment.
2. **Strict event-delivery boundary:** `MeasuredFactualPolicy` enforces that a policy resolves its last chosen action before another choice, that observed feedback exactly matches the chosen action and pre-action public observation, and that delivered events have increasing logical timestamps, distinct provenance, correct paid-probe fees and valid reward. The evaluator, not the policy, owns the world. This is **API-level** causal protection only, not an isolation sandbox for adversarial arbitrary code.
3. **Diagnostic resource/fairness accounting:** Exact number of executed actions and probes, gross and net actual reward, fees, online update counts, retained factual memory rows, total frozen+trainable deployed neural parameters, and per-policy measured decision/update CPU wall-clock nanoseconds. Timing alone is **not** an active-FLOPs guarantee; no numeric performance or breakthrough claim can be inferred from CI.
4. **Development-only comparison:** A factory-created fresh policy for every world, with session persistence separately configurable, permits bounded descriptive unit testing on *development rule* configurations. The harness rejects `heldout` configs **before** creating policies, rejects duplicate dev scenarios and cannot be used as an official heldout scientific evaluator.
5. **CI contract assertions:** test the same causal input tensor shapes for hybrid/Transformer/GRU, factual-only GRU gradient flow with a tiny developer fixture (not research training), duplicate/reordered event rejection, terminal-state accounting, exact action/fee totals, memory-reset ablations, unmatched GRU parameter disclosure and heldout training/evaluation firewall.
