# CHM-v4 #1427 — visible-text hard address→value copy (TRAIN-only rule)

**Purpose:** establish whether the NEW CHM-v4 memory question is deterministically recoverable from the exact text a model would see, and separate source selection, code extraction and answer/abstention semantics. **Not a trained AI model, not a benchmark heldout evaluation, not a breakthrough.**

## Frozen source and provenance

Source: already-merged independent benchmark `tam_research/chm_v4_independent_binding_benchmark_1421.py` from [PR #1425](https://github.com/vinceackermann2-sys/tam-research/pull/1425), exact merge `ea874c019e03bfd4ac725677df6a3bf08ad7dd5f`. New file `tam_research/chm_v4_visible_hard_copy_train_1427.py` is additive. The **reader receives only the benchmark's `SealedInput(query,memory_text,answer_options)` object**. It cannot inspect structured Episode, gold candidate, source labels, source roles, target positions, family or counterfactual variant, model weights or outside state. Input grammar and physical `[0000]` source positions are parsed from visible memory text alone. Both model-visible v4 serializer templates are supported:

- Relation: `[NNNN] V4-train-E... references record V4-train-DOC...` or `[NNNN] Record pointer for V4-train-E... = V4-train-DOC...`.
- Code-bearing row: `[NNNN] Code for V4-train-... is CODE-1800x` or `[NNNN] V4-train-... holds access code CODE-1800x`.

Read rule (exactly what a deterministic parser can do, not what a neural model has learned): extract the unique visible queried subject, validate the ordered completed-memory rows and complete set of eight candidate codes, select the LATEST visible relation for that subject if present, follow that document's LATEST payload, else select the latest directly matching subject code, else abstain. Stale noncandidate code `19001` is allowed as one obsolete row; a selected obsolete/noncandidate code, dangling active relation, duplicate/unsorted address, invalid option bag, malformed grammar, ambiguous question or unknown code fails closed.

Each result returns a selected answer/None, selected first physical memory address, selected code payload physical address, and explicit `copy`/ `abstain` action. **No oracle address participates in source selection.** Only AFTER it predicts does the TRAIN-only test harness compare it against evaluator-side `oracle_read`.

## Evidence contract and scope

The test/audit iterates exactly **2,048 TRAIN examples = 64 entities × 4 task families × 8 counterfactual rotations** from frozen v4. For each, it checks selected answer code, first source position, last value source position and correct abstention against the independent benchmark oracle. Include direct, overwritten prior values, rebinding of old to newer document, negative query with all eight candidate values present in unrelated records, every answer permutation and both text templates. Unit tests inject malformed/duplicate/ambiguous cases and verify failure. A runtime monkeypatch stops and reports if any **development or test episode** is generated by the audit. No old V3 scored holdout generated.

The expected **2048/2048** correct for this purpose-built rule is a *required parseability engineering gate*; it is **NOT a model accuracy result, a scientific confidence bound, a trained 100M inference score, or evidence of learned retrieval**. The parser is an explicit handcrafted algorithm for the known two text templates. Its purpose is to show where the answer is and what learned address/value/answer-gating modules must reproduce rather than calling a soft argmax a hard read.

The separate future learned comparison must use entirely new unscored 16-development/32-test independent CHM-v4 entity groups, grouped uncertainty by independent entity, compute and supervision matching to a Transformer baseline, and preregistered answer-vs-abstention and first/second-hop thresholds, in a unique CPU-only first-run workflow. No TEST construction/scoring during this implementation PR or CI.
