# Conv7 proposed 200M pilot — source-bound CPU stream parity

Status: **synthetic CPU-only sampler audit, NOT engineering/scientific evidence**. New checks cover an experimental fairness risk that the previous gradient-and-optimizer tests did not: all three models must draw identical training token sequences and evaluate on an identical, independently reset held-out sequence.

The frozen completed Attention-8 scientific runner and TokenBin source are each locked by exact Git blob hash. The new audit asserts that the scientific runner uses a separate +99,999 compile-warmup generator, +10,000 measured-training generator, and +30,000 final evaluation generator; resets model RNG after warmup; and consumes 64 x 512 x 2 = 65,536 training tokens per optimizer step. The proposed engineering panel consists of 3,052 steps = 200,015,872 exposures per model, from the full 30,518-step cosine horizon. Final evaluation is 50 x 32 x 512 = 819,200 token predictions. No paid engineering seed or spend cap has been assigned.

The tests create *tiny fake uint16 train/validation shards* inside pytest temporary folders. They invoke the **actual TokenBin CPU sampler** independently three times, once for each model identity. Separate fresh generators using the same synthetic seed must produce byte-for-byte equal sample/target digests for the three comparators, and a distinct held-out stream. Sampling compile warmup must not perturb a restarted training stream. The audit explicitly rejects the real Modal volume path and large datasets.

This ensures CPU sampler and seed derivation parity as a **design contract**, not real proof that future GPU execution, torch.compile, BF16, actual frozen corpus, or each model's training loop will use matching streams. A real runner still needs concrete provenance, dataset SHA256, durability on actual Modal storage, unique authorized engineering seed/job, budget ceiling and stop-on-error safeguards. No H100 run, actual seed consumption, scientific replication or scale-up is permitted by this work.
