## Frozen experiment

- Arms: **A** trained tiny causal Transformer with answer CE, **B** identical-initialization two-hop pointer + answer CE + 0.4×first/second source-position CE (train-only), and **C** identical-init pointer without pointer CE. The pointer output is a soft two-hop answer mix; its reported hard argmax indices are **diagnostics and not a sequential hard-read rollout**.
- Each arm takes the same **48 train episodes** and 48 optimizer steps, same order, LR 0.005, weight decay 0, 128-position memory, single CPU thread. Original source includes a bound on steps. Model parameters are counted exactly and required within 1%; **FLOPs or supervision-label parity are NOT established**.
- Panels: `development` and `test`; one split-specific, entirely heldout entity index **0** per family, eight full counterfactual variants per family. Thus **32 heldout examples per arm/split** (8 direct, 8 overwrite, 8 two-hop, 8 no-match) and **192 total predictions**, across 3 arms. This gives ONE independent entity group per family/split; no valid confidence interval or statistical superiority inference. No hyperparameter tuning from development/test, no test repeats.
- Model API receives **only** `SealedModelView(query,memory_text,answer_options)`, with positions/subject names visible as ordinary serialized text. Gold candidate IDs, family/variant identifiers, source oracle positions and internal role masks are evaluator-only, read **after** each inference. Every positive variant uses a matched code-token multiset, with target-to-decoy swaps and unchanged layout/identities.
- Report EVERY prediction with candidate code or abstention, confidence, first- and second-hop selected visible-token indices for pointer arms, gold code and gold visible source indices on evaluator side, model name, family, split and entity. Include family-wise totals/accuracies and no-match false positive count separately, unique predictions per 8-way group, gold/predicted address-index matches and answer-following rates.
- Report the three analytic controls (query only, code-redacted layout, bag of values only), each **12.5% for positive eight-way groups**; always-abstain negatives separately. Include exact parameter counts, train token count, total CPU train wall time across arms, single additional non-updating forward+backward timing per arm, and heldout inference time per arm/split.
- **No threshold was preregistered to declare a win**. Archive actual scores even if chance-level or worse. If workflow CI/report fails, freeze exact run and report failure—not a breakthrough. Keep all 192 case records in a durable Actions artifact, with source commit and immutable blob proof.

## Known limits

The synthetic generator has four tiny families, templated English, new split/entity namespaces, one tested model init and only 48 train steps. The large shared hash embedding dominates parameter counts, and equal parameters do NOT imply equal FLOPs or information budget. The pointer loss receives extra gold source labels during TRAIN, so its comparison with answer-only Transformer is **not matched supervision**. The model's first and second choices are derived from differentiable soft attention; the exported argmax indices cannot establish hard sequential two-hop retrieval. Confidence intervals are not meaningful for one independent group per family. No general language-model ability, scientific advantage, 100M scaling, or architectural breakthrough can be inferred from a positive synthetic result.

A later scientific 100M GPU experiment would require a new preregistered matched-compute protocol, parameter and supervision accounting, unique immutable seed reservation, capped spend and separate explicit run authority. **The old seed 2013161 remains consumed forever.**
